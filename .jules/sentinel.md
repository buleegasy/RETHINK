## 2024-05-24 - Admin Token Timing Attack Fix
**Vulnerability:** The admin router used a simple string comparison (`providedToken !== adminToken`) to validate the admin token. This was vulnerable to timing attacks, as regular string comparison checks characters one by one and returns early upon mismatch, allowing an attacker to incrementally guess the token by measuring the response time.
**Learning:** Hardcoded tokens or passwords should never be compared using direct string equality operators (`==` or `===`) in authentication routes. This allows attackers to perform a timing attack to extract the secret.
**Prevention:** Use a constant-time comparison function, such as `crypto.subtle.timingSafeEqual` or a manual constant-time XOR comparison loop, to compare secrets without leaking information about the matching prefix length through response timing. Always ensure the lengths are checked beforehand, as constant-time comparison generally requires inputs of the same length.
